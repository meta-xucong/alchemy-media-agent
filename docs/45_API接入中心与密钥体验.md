# API 接入中心与密钥体验

## 范围与权威
本轮新增用户明确要求的 API 密钥 UI；上一轮仅有 Bearer Session 适配。
当前仓库没有可直接调用的 Alchemy 用户密钥创建/撤销接口。
新增的是原 Veyra 账户的可撤销访问凭证，不是账户、登录、余额或计费重构。
密钥只解析回现有 user_id；仍进入原 V3 HTTP 鉴权、审核和费用路径。
不改 Brain、Provider、任务、生成、审核、存储或原五个低层 MCP 工具。

## 极简用户体验
用户页与手机页增加「API 与 MCP」入口，打开统一接入中心。
默认无需填写参数即可创建；名称可选，默认90天有效，最多5个有效密钥。
创建后完整密钥只显示一次，可复制密钥、API示例、已安装 MCP 的连接配置。
列表仅有名称、脱敏密钥、状态、最近使用、停用操作；停用需确认。
提供只查询项目的 API 示例，不自动请求或重试；不增加非必需的前端连接测试操作。
管理员原设置页显示密钥概览，独立管理页可筛选、分页并停用密钥。
请求数是验证通过的 HTTP 请求数，不冒充生图数量、费用或成功结果。

## 最小安全边界
创建、管理与管理员接口仅接受原登录会话；密钥不能创建其他密钥或进入后台。
密钥仅通过 Authorization Bearer 使用，限定现有产品路由白名单；不接受 Cookie 密钥。
服务端只保存随机密钥的 SHA256、末位标识和原账户ID；明文不落日志或浏览器存储。
每次验证继续查询原账户是否有效；禁用账户、撤销、过期及错误密钥均不能调用。
复用现有管理员角色校验，不相信前端隐藏按钮；写操作检查同源及专属请求头。
SQLite 是凭证的小型持久索引，仅一张表，不含余额、任务或新账户数据。
创建失败/响应丢失不盲目重试；先刷新检查，丢失完整密钥后停用再创建。

## 开发与验证要求
隔离工作区开发；保护主目录另一会话的未提交 V3 文档。
覆盖密钥创建/使用/跨账户/撤销/到期、管理员拒绝、敏感信息不泄漏及并发限制。
浏览器验证桌面/手机、空列表、复制失败、创建失败、停用确认与登录状态。
提供真实 HTTP/MCP 适配验证，不新增付费生图；实机扣费验收仍交测试同事。

不显示虚假的“已复制”提示；MCP 配置明确仅适用于已安装插件。
本轮一次包含程序化剪贴板和连接测试的 UI 写入被工具安全检查阻止，未改用其他执行通道重放；
最终采用上述原生选择方案，去掉非必需的前端连接测试。密钥实际 HTTP/MCP 验证由隔离测试覆盖。

## 接手与使用
- 桌面顶部、我的账户、手机顶部：API 与 MCP / API 密钥，进入 `/api-access`。
- 管理员原 `/admin/billing` 页展示概览，进入 `/admin/api-access` 管理。
- 原账户登录后点创建，无必填配置；完整密钥只在当前弹窗显示。
- 复制采取选中后使用系统复制；API 示例只查项目，MCP 连接片段用于已安装插件。
- 原插件 `ALCHEMY_PRODUCT_SESSION_TOKEN` 兼容填入新 Key 或旧会话，无需改工具参数。
- Key 只用于现有 V3 项目/素材/生成/查询/选择/下载产品路由；不开放 V1/V2、管理与低层 handoff。
- 用户和管理员都能停用；默认90天过期。已接受的生成不因撤销被删除或自动退款。
- 概览统计有效/全部密钥与已认证请求，后者包括查询和失败的业务请求，不是生成或费用统计。

## 部署与维护边界
重启原 Alchemy Web 服务并更新静态文件即可，无新进程、依赖、账户或账本。
凭证索引在现有 media_store 根目录 `api_access/keys.sqlite3`，随原数据卷持久化和备份。
只存 SHA256、遮罩和原账户ID；不要把测试库当生产库，也不要将数据卷提交 Git。
公开访问沿用原 HTTPS 和登录部署；本次不修改监听地址、反向代理、SSO 或计费配置。
回滚至不支持 API Key 的旧代码后，新密钥无法使用，旧会话仍可按旧版本使用；不要删除凭证数据。
其他会话的 V3 连续性方案独立保留，不参与本次 API/前端改动。

## 验收重点
检查新建/停用/过期/原账户停用、跨账户列表和输出拒绝、Key不能进入管理/签发自身。
检查关窗、Esc、离开页面和切换账户时及时清理完整密钥，不进入本地存储或 URL。
用原 Web 账户和新 Key 对照同一项目，验证生成受理参数、账户和计费入口一致。
本地测试使用隔离的原账户服务替身及真实 SQLite/HTTP/MCP/Chrome，不使用生产密钥或真实扣费。
上线同事还需核验实际 SSO/账户状态、原生成费用、实际 Codex 配置与手机系统复制操作。
