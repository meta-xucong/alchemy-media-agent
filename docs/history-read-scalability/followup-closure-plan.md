# PR29 复审收尾：资源边界与图片发布隔离

## 基线与判断

固定基线 `fd259486bebdda58eab506638991cdb04f9f1047`。上一轮热读取和准入证据有效，但只覆盖普通服务端热页，不覆盖浏览器累计页、异常来源扇出、首次构建、磁盘保留或文件发布权限。本轮用户明确要求继续优化上述缺口。

不修改或删除生产图片、Job、收藏、用户记录；不调用 Provider，不操作 VPS，不合并。使用同一独立云端功能分支，保留主工作区和原始证据。历史数据长期保留意味着权威磁盘容量仍随数据增长；本轮不擅自制定过期删除策略。

## 修正模型与权威

| 缺口 | 责任层 | 最小修正与验收 |
| --- | --- | --- |
| 文件已落盘但 owner 尚未持久化 | 发布与可见性 | 写文件前持久化输出 ID/显式 owner 的发布预约；匹配规范 Output 提交前不可读取。索引、原图、缩略图、预览、分享本地读取共享边界。未知旧记录不可由 Session 推断 owner |
| 请求触发完整建库/导入 | 维护与就绪 | 普通列表只检查有界就绪状态，未准备返回可重试 503；完整导入/构建/恢复只由显式维护操作执行。部署前验证存储根、版本、导入状态、磁盘余量及构建结果 |
| 单 output ID 多来源 fetchall | 归属与胜出投影 | 归属使用标量聚合，候选按有索引顺序流式遍历；只保留当前 session 及全局胜出项。不能通过来源数截断忽略 owner 冲突 |
| 浏览器累计所有已浏览页/收藏 | 前端状态与分页 | 固定当前历史窗口及卡片数量，支持向前/向后重新取页，无永久页缓存；收藏由服务端过滤分页，避免客户端读完整历史 |
| 派生索引复制大 payload | 派生数据模型 | 任务级展示字段每 Job 保存一份，输出保存差异/引用；可按键取得的 manifest 不再复制整份 payload。保持页面级解码及原响应内容 |

派生 schema 升级只重建派生表，不重放已删除的 JSONL 记录，不改权威导入 receipt。原版本的来源映射、压测结果保留为历史基线，不能拿旧指纹证明新实现。

## 跨组件合同

- 发布预约不是 Session 归属猜测，也不是“文件存在就公开”。匹配 canonical Output 是新受控输出发布条件；失败/取消后预约继续阻止散落文件公开。
- 删除重试的 owner claim 可以授权清理，不能用于放行原图或预览读取。
- 旧无预约且关联已知 Job、但不在其已发布 outputs 中的文件按未发布/未知处理。真正孤立的旧公共文件仍需显式兼容规则；不得把所有旧数据统一误判为新私有数据。
- 普通请求不得借“严格校验”重新全量导入旧文件。缺失或不兼容的就绪状态返回维护要求，显式导入仍保持严格失败回滚。
- 新增可选 `favorite=true` 不改变默认列表响应形状。收藏与历史双重权限过滤；只解码页面 payload，不在 Python 组装全部收藏 ID。精确收藏交集计数若仍需 O(F) 标量工作，应披露，不宣称所有查询 CPU 恒定。
- 前端保留历史的完整可访问性，通过重新取页访问已淘汰内容。72 条窗口限制不得变成永久只显示前 72 条；Hero/选择器/账户采样单独有界，V3 不改。

## 验证与上线门禁

1. 先写失败回归：预约前后、落盘后/规范记录前、取消、重启、删除重试、owner 冲突和跨账号读取；公开旧记录的兼容正例同时保留。
2. 未准备/旧 schema 的列表不得调用构建、目录全扫描或 JSONL 解码；显式准备成功后读、失败回滚、不同存储根恢复都有覆盖。
3. 同一 output 的 100/1k/10k 以上来源分别验证归属、每 session 胜出、排序和内存增长；一条超大权威 Job 的解码边界单独说明，不能冒充所有异常输入完全常量内存。
4. 浏览前后数百页、反复收藏/切换/取消/换账号，检查保留数组、DOM、请求数及游标语义；VM 合同与真实浏览器证据分开。
5. 对同一合成数据比较派生库/WAL/逻辑写入和显式准备耗时；不重复之前已完成的旧主线全矩阵。新版本热读及压力探针绑定新指纹。
6. 最终集成回归、独立审计、更新 Draft PR，并核对新 head 的 CI。完成代码范围不等于生产迁移或 2 核 2G VPS 放行。
