## 基线、结论与范围

审计基线：`5a33c05e3f54dbef786eb179973ec1407511b4e4`。本轮工作使用独立功能 worktree；既有主工作区改动不属于本轮。

现有只读 VPS 观察没有证明持续内存泄漏，也没有证明两页读取压满 VPS。本轮独立源码审计确认的是可重复发生的工作放大：V1 每次重建临时历史表，Lab 在全量窗口上转换、过滤和排序，V2 部分查询形状仍需排序大量索引行，两个前端壳存在隐藏模块与账户页请求放大。

只治理列表/历史读取和与其直接关联的查询、派生索引、按需载入、只读准入。不调用真实 Provider，不修改业务图片、Job、收藏或用户数据，不提高 API/计算 worker 数，不执行 VPS 切换或生产迁移。合成测试只写隔离夹具与可丢弃派生数据。

## 独立审计：责任路径和增长模型

| 路径 | 基线工作量 | 本轮修正目标 |
| --- | --- | --- |
| V1 `_list_image_history_sync` | 每次解码全部 image Jobs，跨 session 归属判定，读取历史窗口，扫描生成目录，新建临时 SQLite 并再次转换候选 | 一次受控构建，增量更新受影响输出，热查询先筛选排序再读取页面 |
| Lab `list_lab_history` | 先取得最多 10,000 个存在文件的 manifest，再按 owner/类型/mock 筛选和转换，最后排序截断 | 索引化类型、归属、排序和 mock，移除筛选前全局窗口 |
| V2 `list_image_history` | 已只解码页面；admin 全局排序、owner/public OR 查询可形成全量临时排序；精确 COUNT 与 OFFSET 仍有扫描成本 | 覆盖排序索引、互斥有序流合并、事务性精确计数桶；保留分页契约，深 OFFSET 仍有遍历成本 |
| V2 case detail/bootstrap | 每次 keyed detail 的 bootstrap 判空解码整个 active cases；账户最多触发 30 次 | SQL EXISTS 判空，不改变种子导入权威 |
| Desktop/mobile | V1 隐式初始化、72 行取数/24 卡展示、账户五路基础请求、空/失败重复历史回退、隐藏图片绑定 | 按真实模块/面板需求载入，去重，保留 Hero/收藏/账户样本语义 |
| SQLite read admission | 共用两个 worker，满载立即拒绝；已提交任务取消后仍持有许可，正确 | 只读 opt-in 小队列，共用原 worker，保留实际完成前许可和写入路径行为 |

V1 的全局 Job/manifest 排序索引也不匹配：现有 session-first 索引不能消除全局临时排序。仅新增该索引仍不能解决全量 JSON 转换、目录遍历和归属投影重建。

## 不变量和有意修正

1. 归属证据跨 session 汇总。canonical Output owner 优先于 manifest 证据，再优先于所有旧 Job 副本；同层冲突拒绝。文件存在性不得制造公共归属，Session owner 不用于猜测输出 owner。
2. V1 全局与 session 内的显示胜出记录可以不同，权限证据不能随显示范围缩窄。
3. V1 Job 来源原本不要求文件存在；manifest/filesystem 来源要求存在。不得为统一索引而静默改变此区别。
4. Lab 仍是非管理员仅本人可见；不会照搬 V1 的旧公共记录规则。manifest 冲突不能在 Lab 列表绕过权威权限判定，这是明确安全修正。
5. 筛选前 10,000 窗口导致历史不完整。移除该截断是明确完整性修正：窗口内做等价验证；窗口外按独立夹具真值验证，不能假称旧结果完全等价。
6. 删除 claim、所有副本清理、收藏隔离、严格导入与 receipt 不降级。派生索引从当前 SQLite 权威重建，不重新播放可能已删除的 JSONL 数据。
7. 不改变 API 响应形状和 offset 契约。深 offset 仍可有 O(offset + page) 遍历；本轮将 V1/Lab 和 V2 的热页精确计数物化为事务性计数桶，首次构建及维护验证仍是 O(N)，必须分项披露。
8. 外部直接改动文件无法同时满足即时精确全库计数与页面级文件检查。文件库存必须声明受控核对和页面修复的一致性边界，不把缓存存在位宣称为即时磁盘事实。
9. 收藏已改为服务端筛选分页和有界浏览器窗口，不再显式全量下载；向前/向后重新取页保留全部历史的可访问性。账户原 72 行模板统计与 usage 样本不被首屏缩小偷偷改变。错误与成功空结果必须区分。

## 验收矩阵

隔离数据规模为 100、1,000、10,000、50,000 条；只读并发 2/4/8。覆盖多个 owner、session、旧 Job-only、manifest-only、filesystem-only、缺图、mock、时间/ID 相同、重复归属冲突及删除中断。

必须区分初次导入/派生构建、已有索引新进程和重复热页。记录页面 JSON 解码量、应用读取行数、SQLite 查询/VM 工作、目录与文件检查、临时磁盘、CPU、RSS 前/峰值/结束/静置、p50/p95、成功与 503 比例、排队和实际服务时间。SQL trace 不能冒充扫描行数；新进程不能冒充操作系统冷缓存；成功请求 p95 不能隐藏被拒绝请求。

热页不能重复扫描全部 Jobs/目录或重建完整临时库。取消尚未执行的请求不得随后执行；取消已执行请求不得提前释放容量。排队上限和等待时间必须有限，写入路径保持原准入语义。
