# RenderBridge 节点奖励转入余额

用户在账户中心主动将当前全部可转积分转入 Veyra 可用余额。每张有效交付产生 0.02 积分，兑换比例为 1 积分兑 1 个余额单位。可转积分和累计奖励分别展示。提现入口标明满 10 积分，暂不发起任何操作。

Alchemy 根据当前登录账户、节点绑定基线、历史绑定和 Bridge 已接受的真实图片数计算累计合格张数。浏览器不提交账户 ID、兑换金额或张数。统计不完整或计数回退时停止兑换。调用 Veyra 前，Alchemy 在同一份 SQLite 快照内验证绑定归属并保存各绑定所用的计数。节点随后改绑时，以这个已经锁定的计数作为原账户结算下限。

Veyra 仍是余额与兑换回执的唯一写入方。内部兑换接口要求现有服务认证和独立的节点奖励密钥。它锁住同一账户行，在一个 PostgreSQL 事务内读取此前已转入的最大累计张数，仅按新旧差额入账并写回执。重复点击、请求超时后重试、并发提交较旧张数及 Alchemy 重启均不会重复入账。收入发生后复用余额与鉴权缓存失效流程。

旧节点可转的奖励从零已兑换张数开始计算。上线先部署 Veyra 数据库迁移 `249_veyra_node_reward_redemptions.sql` 和内部 API，再在两侧配置同一独立密钥 `VEYRA_NODE_REWARD_CREDIT_TOKEN`。缺少密钥或账本不可用时，现有节点奖励统计仍可读取，转入按钮保持停用。上线验收使用隔离账号，现有账户余额由本人首次点击后变更。

停用兑换可移除独立密钥，已结算的 PostgreSQL 回执和 Alchemy 的绑定计数继续保留。发生余额超时后，可刷新状态或重试原操作。需要回退不识别绑定计数保护的旧版 Alchemy 时，兑换和节点改绑都暂停，直至恢复兼容版本或完成账本对账。

## 计奖、解绑和回执验收

Bridge 只有在 Alchemy 明确接受真实图片交付后才增加可计奖张数。切换前逐个节点核对旧计数和已接受计数。两者一致才可沿用原绑定基线和钱包累计水位。若历史计数有差异，先对账再切换，避免下调仍在使用的基线或重复入账。

Alchemy 的统计和转入共用资格条件。统计不完整、计数回退或钱包不可用时，页面显示转入暂停的原因。转入前仍在写事务中核对绑定版本。所有者可主动解绑，解绑保存截至已核实计数的积分，历史积分仍可转入。重新绑定需要解绑后创建的绑定码及节点确认，新绑定从当时的计数起算。

Veyra 是逐笔回执的唯一来源。Alchemy 展示每笔转入金额、日期和转入后余额，Veyra 管理员余额流水也展示同一笔记录。节点积分转入不计入充值金额。钱包回执支持分页，提现按钮继续停用。
