## 源码确认
- Project create_project_job 的非电商分支合并 `_project_asset_ids(project)` 与当前上传。
- General 默认进入 Doc281 项目来源选择，甚至可能把明确上传降级成空输入。
- `_build_context` 汇总历次 active/selected/uploaded 记录并对所有模式公开源池。
- Central `_has_explicit_user_reference_assets` 把多类参考统一当成已有用户参考，抑制首图候选。
- Provider `_reference_assets` 合并两个兼容数组；`_asset_plan` 创建派生图后仍可能追加原图。
- 旧 Doc73 自动链在共享正式审核前使用第0张图；不能等同本设计的正式主图。
这些代码路径证实了污染风险；尚未读取 VPS 原案例，不将其表述为逐图线上取证。

## 合同歧义的修正
1. §9 unbound→auto 与 §4/5 冲突：解绑是持久抑制，只有明确手动绑定能恢复。
2. 示例 continuity=1、direct=3、physical=3 不能作为固定等式；实际通常为4，去重另记。
3. 模板与 Professional 是两个维度：商品计划归电商；已批准的专业身份绑定可由该合同引用，不能默认扫其他池。
4. 首张正式审核结束才晋升项目主图，不回写已经冻结的当前 Job，不以前置候选冒充正式通过。
5. 普通输入永远一源一原图；已有明确专业多视图/细节几何证据契约不被误删为“重复”。
6. 未知模式/证据/容量须显式阻断或保留待确认，不靠裁剪数量、词匹配或降低审核门槛恢复。

## 最小修正模型
在原 ProjectStore 私有记录内维护单一版本化主图事件流，原子 CAS 替换/解绑。
冻结每个新 Job 的模式来源与主图快照；现有专业/商品合同仍拥有其派生表示。
物理计数在实际物化完成后出具同计划绑定的收据，未知值不伪装为零。
旧接口进入同一绑定服务，历史保留；普通新任务不再从通用源池隐式继承。
