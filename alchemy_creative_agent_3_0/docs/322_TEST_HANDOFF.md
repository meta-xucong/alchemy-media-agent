## 已实现的产品规则
1. 一个项目最多一张当前连续性主图，绑定新图替换旧图，历史不删除。
2. 用户解绑后自动晋升保持关闭；晚到的生成结果及旧选中记录不能补回主图。
3. 自动晋升只接受既定条件下计划位置0的初次正式通过输出，不选择后续或重试替代品。
4. 主图变更只影响新的任务；已冻结任务及其重试保持原快照。
5. Standard/General 只用本次明确上传与0/1主图，不扫描通用源池或专业/商品素材。
6. Professional 只消费显式绑定的冻结版本；资产建立内部步骤沿用原受信入参。
7. E-Commerce 由既有商品事实与逐输出物理计划负责来源/表示；获准人物身份通道独立。
8. Provider 与 MCP 对新产品Job共用冻结 ReferenceInputPlan，核验来源、顺序、哈希和实发数量。
9. 普通3张直接图不会自动扩成原图+crop的6张；另有主图时通常是3+1=4张。
10. 桌面与手机共用主图组件，显示当前主图、本次参考或对应模式的输入说明。

## 必须理解的边界
自动主图在共享正式审核后才晋升，从后续新Job起生效，不回写同一已冻结批次。
直接参考图不是连续性主图；派生证据不是用户上传，不作为当前主图或通用素材展示。
Professional 合同批准的互补证据视图、E-Commerce 的明确物理计划仍由原专属规则管理。
逻辑来源数量、派生数量、最终物理数量分别记录；未物化的专业计数不伪装为0。
解绑不会删除输出、取消已有冻结任务，也不会自动撤销其已批准输入。
旧冻结Job保留原合同；旧历史无可靠归属、无正式审核或多图歧义时不自动迁移使用。

## 实测顺序
- 先核对服务实际加载的提交号与静态资源版本，再测试，不只看磁盘Git号。
- 普通项目先保留旧上传/选中历史，再新任务传3张当前图：实发应为3个原图输入。
- 新任务不传图：不得读取上次3张图；明确绑定主图后只增加该一张连续性输入。
- 手动绑定A、替换B、解绑、刷新、重启：唯一主图、历史保留、解绑不复活。
- 已冻结任务期间改绑定：该任务和重试仍读原快照，下一新任务读取新状态。
- 同时两次绑定/绑定与解绑：旧版本请求应冲突，不覆盖较新的用户决定。
- 人物多图任务只有计划位置0正式通过且符合条件时自动晋升；人工复核/失败不晋升。
- 旧Doc73只有来源与正式交付证据可验证时迁移；未审核/多候选/跨账户记录不迁移。
- Professional 有绑定/无绑定、版本变化、资产建立首阶段分别测试，不混入旧普通上传。
- E-Commerce 普通商品、已授权人物、明确连续性主图分别核对每个输出的冻结物理计划。
- Provider 与产品MCP核对同一来源/表示/顺序/数量；低层Native旧失败分支需单独验收。
- 桌面/手机核对主图卡片、本次参考、正式输出/复核/历史；断网不重复提交，切换项目不串提示。
